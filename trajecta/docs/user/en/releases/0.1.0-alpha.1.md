# 0.1.0-alpha.1

`0.1.0-alpha.1` is the first Trajecta product release. It provides a complete
local workflow from a Case and locked meteorological dataset to verified
trajectory results. The release is intended for evaluation, reproducible
scientific workflow development, and early operational use on supported hosts.

## Packages

| Platform | Archive | Executable |
| --- | --- | --- |
| Windows x86_64 | `trajecta-0.1.0-alpha.1-windows-x86_64.zip` | `trajecta.exe` |
| Ubuntu 24.04 x86_64 | `trajecta-0.1.0-alpha.1-linux-x86_64.tar.gz` | `trajecta` |

Both archives contain the native meteorological runtime, ecCodes definitions,
four example projects, data-preparation helpers, bilingual offline quickstarts,
an SBOM, and a third-party license inventory. The CFSR demonstration data is a
separate release asset so the same files can be used with either platform
package.

Download the archive and its `.sha256` file from the
[0.1.0-alpha.1 release](https://github.com/origin652/trajecta/releases/tag/v0.1.0-alpha.1),
then follow [Installation and first steps](../getting-started/index.md).

## Scientific workflows

The release includes four documented workflows:

| Workflow | Population | Example project |
| --- | --- | --- |
| Domain-fill moisture | Dry-air domain filling with water-vapor mass | `examples/domain-fill-cfsr` |
| Release trajectories | Configured release events | `examples/release-cfsr` |
| Air-mass domain fill | Dry-air finite-volume population | `examples/air-mass-era5-pressure` |
| Stratospheric ozone | Domain filling with ozone-specific seeding | `examples/ozone-era5-hybrid` |

All populations use the same spherical midpoint RK2 integrator and typed
meteorological query path. Cases can integrate forward or backward in physical
time. Limited-domain runs record boundary births and terminations with stable
particle identity.

The [Tutorials](../tutorials/index.md) provide complete project files and command
sequences. Scientific definitions and lifecycle behavior are described under
[Concepts](../concepts/index.md).

## Meteorological data

Supported product families are:

| Family | Vertical coordinate | Product readers |
| --- | --- | --- |
| CFSR pressure | Pressure levels | Pure Rust and native ecCodes paths |
| ERA5 pressure | Pressure levels | Pure Rust and native paths for the prepared product |
| ERA5 hybrid | 137 hybrid model levels | Pure Rust and native paths for the prepared product |

Dataset Profiles map exact source metadata into canonical fields and derived
quantities. `project data-plan` reports required files before they exist;
`project finalize` creates DatasetLocks after data preparation. The separate
Python helper can retrieve supported CFSR and ERA5 requirements without adding a
new CLI command.

The four-file CFSR demonstration asset is sufficient for the 15-minute
domain-fill quickstart. ERA5 tutorials use provider-supplied data and the
documented CDS credential channel.

## Project and configuration control

The CLI supports incremental machine and project setup:

- initialize, read, set, unset, list, and validate machine configuration;
- initialize a project and edit named Case/Profile mappings;
- maintain draft projects while some fields or data are pending;
- generate deterministic data plans;
- inspect and lock prepared meteorological data;
- run `doctor --deep` for configuration, filesystem, SQLite/WAL, lock, and data
  checks;
- finalize a project only after its document and data bindings are complete.

Project document paths are contained within the project root. Failed validated
updates leave the prior file unchanged through temporary-file and atomic-rename
writes.

## Local queue and process model

Runs use a durable local daemon, job catalog, and separate worker process.
Foreground mode waits for the submitted attempt. `run --detach` returns after
queue admission, allowing another terminal or session to follow the same work.

The queue provides:

- explicit CPU-slot and memory reservations;
- FIFO scheduling with bounded small-job backfill;
- persistent job status and fan-out event streams;
- safe cancellation at a macro-step boundary;
- force cancellation with retained forensic files;
- daemon restart recovery using PID plus process-start identity;
- rerun as a new attempt in the same job series;
- preservation of completed attempts;
- a dry-run prune plan for storage review.

`job prune` does not delete files in this release. Queue operation and recovery
procedures are collected in [How-to Guides](../how-to/index.md) and
[Operations](../operations/index.md).

## Results

Each attempt has its own result directory. A successful closeout contains:

| Product | Contents |
| --- | --- |
| `run-manifest.json` | Software, resolved input, dataset, numerical, lifecycle, termination, mass, SQLite, and provenance identity |
| `particles.sqlite` | Run, particle, mass, output event, sampled state, and termination tables |
| `provenance-bundle.json` | Source-record and transformation assignments for sampled fields |
| `run-report.md` | Regenerable human-readable summary created by `run report` |
| Forensic/log entries | Attempt-specific runtime material when present |

Result commands can:

- inspect the manifest and available table counts;
- run quick or full verification;
- stream selected or all particle trajectories as human text, JSON, or JSONL;
- generate the fixed-path Markdown report.

SQLite is an advanced read-only interface. The primary result commands validate
the relationship among manifest, database, and provenance before presenting a
summary.

## Machine output

The global `--format json` option returns one `trajecta.cli-output/v1` envelope.
Stream-capable commands can use `--format jsonl`, where each line is a
`trajecta.cli-stream-item/v1` object and the stream ends with one summary item.

Machine-mode diagnostics use stable codes, and usage errors retain process exit
code `2`. The complete command tree and format schemas are generated under
[Reference](../reference/index.md).

## Compatibility notes

This is the first product release, so there is no earlier Trajecta project format
to migrate. Keep the following files with a scientific run when future alpha
versions are evaluated:

!!! tip "Keep the checksum with the archive"

    The checksum identifies the exact package when release assets are copied or
    moved.

- original archive checksum and build manifest;
- project index, resolved Case, and resolved RunProfile;
- DatasetLocks and source meteorological files or hashes;
- complete attempt directory;
- the matching versioned manual.

Document and stream schemas carry their own version identifiers. Public Rust
APIs remain contributor-facing during alpha.

## Known limits

- Product packages are published for Windows x86_64 and Ubuntu 24.04 x86_64.
- Scheduling is local; there is no remote or cluster backend.
- Plugin loading has not been implemented.
- The prune command reports a dry-run plan and does not remove files.
- A general derived-product exporter is not included. Trajectory streaming and
  read-only SQLite access are available.
- Safe cancellation closes a partial result; it does not resume the same
  numerical attempt later.
- Dataset retrieval remains an explicit helper step followed by project
  finalization.

The complete operational boundary is listed in
[Alpha limits](../reference/alpha.md).
