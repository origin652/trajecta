# 操作指南

本章按照要完成的具体工作组织内容，适合已经了解 Trajecta 项目基本结构的读者。第一次运行可从
[十五分钟快速入门](../getting-started/quickstart.md)开始；需要从配置到结果完整走一遍科学案例时，
可选择相应的[教程](../tutorials/index.md)。

**命令中的占位符**

本章统一使用以下三个占位符：

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `PROJECT` | 项目目录，或项目索引文件的路径 | `examples/domain-fill-cfsr` |
| `PROFILE` | 项目索引中登记的运行配置名称 | `product` |
| `RESULT` | 任务系列 ID、运行 ID，或某次运行的结果目录 | `runs/0198.../attempt-1` |

项目文件中的相对路径始终以项目根目录为基准。命令示例使用正斜杠；页面标明的 PowerShell 和
Ubuntu 命令均可按原样使用。

## 新项目常用顺序

一个项目通常经历以下阶段：

1. 创建本机配置，设置 Trajecta 可使用的 CPU 和内存。
2. 初始化项目，加入案例（`Case`）和运行配置（`RunProfile`）。
3. 在项目处于 `configured` 状态时生成资料计划。
4. 下载或整理气象资料，并抽查文件的时次和内容。
5. 执行项目定稿命令 `project finalize`，生成资料锁（`DatasetLock`）。
6. 以前台方式运行，或把任务提交到后台队列。
7. 跟踪持久化事件，随后验证并读取终态结果。

项目文档先于气象资料准备完成是正常用法。`project validate` 负责检查已有配置；
`project finalize` 才会要求本地资料满足案例的覆盖范围和能力。

**机器可读输出**

所有命令都可通过全局参数 `--format json` 返回一个完整 JSON 响应。事件和轨迹等流式命令还
支持 `--format jsonl`，每行都是一条独立记录。自动化程序应根据 `schema_version` 和稳定诊断码
处理输出，相关结构见[结构定义参考](../reference/schemas.md)和
[诊断码索引](../reference/diagnostics.md)。

!!! tip "全局参数的位置"

    `--format`、`--config` 和 `--project` 放在子命令之前，例如
    `trajecta --format json --project PROJECT project status`。

## 修改已经用于运行的配置

`config set`、`config unset`、`project set` 和 `project unset` 会先在内存中构造完整新文档，
通过校验后再原子替换原文件。命令失败时，原文件保持不变；诊断信息会指出相关字段和文档。

项目定稿后，解析出的配置会与一份气象文件清单绑定。下列变化需要在下一次提交前重新执行
`project finalize`：

- 修改案例时段、区域、粒子群或所需物理能力；
- 修改运行配置中的资料映射或读取器；
- 更换、增加或删除已经锁定的气象文件；
- 改变资料目录或内置资料配置。

已有执行轮次会在各自的结果目录中保存当时使用的解析后文档和溯源信息。重新定稿不会回写
旧结果。
