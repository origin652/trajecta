# 扩展机制

Trajecta `0.1.0-alpha.1` 尚未实现插件机制。当前发布包中没有插件清单、发现目录、动态加载器，
配置文件和命令行也没有插件入口。本页介绍源码中已经分开的功能模块，并记录后续设计需要考虑的
接口。这里没有可直接使用的插件配置。

## 当前可供用户使用的接口

当前版本可供用户直接使用的接口包括：

- `trajecta` 命令行；
- 本机配置和项目配置；
- 案例、运行配置、资料锁、运行清单与数据流结构定义；
- 结果目录文件和 SQLite 只读结构；
- 稳定诊断码和进程退出码。

配置解析会拒绝未知字段。未来设计中的字段若提前写入当前配置，会得到结构诊断，不会被静默
忽略。

## 源码中的内置边界

Rust 工作区在这些公开接口之下划分了若干实现边界：

| 边界 | 当前职责 |
| --- | --- |
| 气象读取器 | 打开 GRIB 或 NetCDF，并提供统一格式的资料帧 |
| 资料配置目录 | 把服务方变量和变换映射到规范字段 |
| 粒子群策略 | 管理初始化、出生、终止和质量账本 |
| 臭氧赋值规则 | 按名称选择内置规则及其字段要求 |
| 积分器和边界模型 | 推进粒子状态并处理物理边界 |
| 粒子状态输出端 | 写入 SQLite 和溯源赋值 |
| 任务存储与本地 IPC | 持久保存队列生命周期，并与守护进程通信 |

这些接口供源码贡献者使用。新增内置实现时，需要与其配置、科学约定和验证流程一起进入工作区，
再由新的源码构建或发行包分发。

## 当前如何扩展源码构建

需要新气象资料配置、粒子群模型或输出端时，可以在 Rust 工作区分支中完成：

1. 确定负责该功能的 crate 和现有 trait 或登记表。
2. 使用新的稳定模型 ID 添加实现。
3. 在案例或运行配置模型中定义字段与校验。
4. 声明所需气象能力和溯源标识。
5. 增加可重复运行的单元测试和真实资料集成路径。
6. 若持久状态发生变化，同步更新结果验证。
7. 以独立源码修订构建和分发 Trajecta 二进制。

内置资料配置也随源码分发。运行配置可以选择已有资料布局，但读取操作和字段变换仍来自编译进
二进制的实现。[开发手册](../developer/index.md)介绍 crate 职责、气象查询、数值运行、测试和
发布流程。

## 为插件预留的方向

未来插件设计可以从一个范围明确的扩展类型开始：

| 方向 | 需要定义的问题 |
| --- | --- |
| 资料读取器 | 文件权限、字段能力、网格标识、缓存和原生依赖 |
| 字段变换 | 单位与类型检查、操作标识、可重复性和溯源参数 |
| 粒子群模型 | 出生与终止、携带状态、质量账本和结果验证 |
| 输出产品 | 外部目标目录、结构归属、流式写入、部分失败和摘要关系 |
| 运行时集成 | 进程隔离、资源核算、取消、事件传递和恢复 |

首个插件格式还需要定义包标识、兼容版本范围、能力声明、版本协商和安装流程。参与科学计算的
扩展还需要在结果中记录算法名称、版本和相应的验证状态。

## 运行标识和溯源要求

当前内置模型 ID、资料配置散列、软件版本和解析后文档都会写入结果。插件若参与科学计算，
也需要留下同等粒度的标识信息，至少包括：

- 插件名称、版本和内容散列；
- 可兼容的 Trajecta 软件版本与结构版本；
- 声明能力和模型 ID；
- 提供给插件的规范化配置；
- 会影响输出的原生或外部依赖；
- 插件生成字段的来源与变换链；
- 执行中途停止时的失败信息。

插件加载、隔离和结果标识需要共同设计，因此当前版本没有预设插件清单格式，也没有可复制的示例
配置。

## 文件、网络和凭据

未来的数据服务或运行时插件可能需要文件和网络访问。插件约定需要明确权限范围，并规定凭据如何
传入，使其不进入项目文件、命令记录、任务事件、运行清单和溯源信息文件。

当前资料助手沿用服务方官方凭据存储，Trajecta 文档只保存请求参数与文件内容标识。后续插件设计可以
延续这一分离方式。

## 为后续扩展保留可移植性

项目可以通过现有约定为以后扩展保留空间：

- 案例通过逻辑资料 ID 引用气象资料；
- 本机路径和读取器选择放在运行配置；
- 派生分析产品写到结果目录之外；
- 归档结果时保留解析后文档与验证记录。

这些约定属于当前产品模型，不依赖未来插件机制。

## 后续设计入口

插件提案成熟后，可以先为一个明确扩展类型编写架构决策，再随实际实现加入结构定义、CLI、
打包和文档。当前发布包使用[参考手册](../reference/index.md)列出的内置模型。
