    开发架构¶

    Trajecta 的 Rust 工作区包含五个主要 crate。目录划分遵循一次模拟的处理顺序：先解析文档， 再准备气象资料，随后推进粒子并写出结果，任务系统负责调度，命令行负责呈现。沿着这条链路定位 修改，可以较快找到规则的归属位置。

    本节面向参与 Rust 实现、测试设施、打包工具或文档维护的贡献者。已经提供给使用者的公开接口 集中列在参考手册。

    仓库目录¶

    路径 负责内容 常见修改
    crates/trajecta-case 案例与运行配置文档、单位、本地引用、诊断和资料锁类型 新增可验证字段、引用规则或文档诊断
    crates/trajecta-met 数据集运行配置、源文件读取、原生网格、垂直坐标、字段推导、插值和查询准备 新读取器、推导字段、垂直坐标规则或查询优化
    crates/trajecta-core 模拟时钟、粒子状态、RK2 积分、边界、粒子群、输出、运行清单和结果验证 数值规则、生命周期、输出记录或科学检查
    crates/trajecta-job 持久化本地任务数据库、调度器、执行轮次、事件历史、IPC、守护进程与工作进程控制 队列转换、恢复规则、资源决策或任务事件
    crates/trajecta-cli 命令解析、项目组装、调用分发、机器可读响应和结果视图 新命令、输出格式、项目操作或退出码映射
    testdata 公开结构定义、冻结的接口约定、小型测试资料和验证输入 与结构定义一致的示例或带版本的约定样例
    examples 教程及自动快速入门使用的完整项目 可执行工作流或样例配置
    tools 打包、参考页生成、资料获取和验证程序 发布门禁或可重复维护操作
    docs/user 公开双语手册 用户、运维和开发文档
    docs/engineering 计划、提示词、执行报告和历史设计资料 工程记录；不会进入公开站点

    工作区的依赖方向如下：

    trajecta-case
    └── trajecta-met
            └── trajecta-core
                    └── trajecta-job

trajecta-cli 依赖四个产品库。
trajecta-core 还会直接使用 trajecta-case 的文档类型。
trajecta-job 会使用 trajecta-case 中已经验证的输入类型。

    底层 crate 不会反向调用 CLI。数值执行也不依赖守护进程，因此直接集成测试和守护进程启动的 工作进程可以共用同一条 trajecta-core 执行路径。

    从命令到结果¶

    项目运行按以下顺序经过工作区：

    1. trajecta-cli 查找 trajecta-project.yaml，按名称选择运行配置，并在项目根目录内解析相对路径。
    2. trajecta-case 解析案例和运行配置。解析过程会拒绝未知字段，展开组件引用，规范化单位， 最后返回顺序稳定的诊断。
    3. project finalize 将解析后的文档绑定到资料锁。资料锁记录本次运行使用的文件及其散列， 同时保存时空覆盖范围、能力集合和资料集标识。
    4. trajecta-job 把请求写入本地任务数据库。调度器预留 CPU 槽位与内存，分配执行轮次 ID， 然后启动工作进程。
    5. 工作进程调用 trajecta-met 建立锁定资料的索引，生成规范字段，选择所需的资料帧窗口， 并准备查询结构。
    6. trajecta-core 创建粒子群，按照带符号的宏步推进。边界处理、粒子出生、终止和 定时输出遵循稳定的生命周期顺序。
    7. 输出事务关闭 SQLite，写入溯源记录，并用终态运行清单替换运行中清单。任务数据库 记录相同的终态，同时追加最后一条事件。
    8. 结果命令读取公开运行清单和 SQLite 文件，不会再次启动数值计算。

    气象资料与数值路径详细展开第 3 至第 6 步。输出与运行时 说明任务入队、执行和终态恢复。

    修改应从哪里开始¶

    修改目标 首要入口 后续检查
    增加案例字段 trajecta-case 的模型与结构定义 展开逻辑、示例、自动生成的结构定义参考页
    增加资料系列 trajecta-met 的运行配置、清单与读取器 资料锁能力要求、真实固定测试资料、软件包矩阵
    修改插值 trajecta-met/query 或 trajecta-met/grid 科学容差、确定性、性能
    修改粒子运动 trajecta-core/integrator 正反向回放、边界、输出摘要
    修改粒子群 trajecta-core/population，气象推导放在 trajecta-met 质量账本、出生、稳定 ID、教程
    增加结果字段 trajecta-core/output 与运行清单 SQLite 结构定义、验证、结果检查、参考页
    修改队列行为 trajecta-job 任务数据库事务、IPC、CLI 事件流、恢复测试
    增加命令 trajecta-cli CLI 约定、JSON/JSONL 响应格式、退出码、自动参考页
    修改软件包内容 tools/m5_a4_package.py 构建清单、SBOM、全新解压测试、两个平台
    修改公开文档 docs/user/en 与 docs/user/zh-CN 严格构建、链接、双语结构，以及开发预览与发布站点的 SEO

    一项功能可能跨过表中的多行。新规则应放在拥有该含义的层中，后续适配层直接调用它，避免在 命令行、工作进程或测试工具里另写一份实现。

    跨 crate 的数据约定¶

    下列对象会在多个层之间传递。审查修改时，需要同时查看生成位置和读取位置：

    数据或接口 生成位置 主要读取位置 兼容性重点
    已解析的案例与运行配置 trajecta-case CLI、核心运行器 字段含义、默认值、规范化单位
    资料锁 项目定稿 气象资料加载器、运行清单构建器 文件标识、时空覆盖、能力要求
    已准备查询与类型化样本状态 trajecta-met 积分器、边界采样器、输出 执行阶段无隐式文件 I/O；无效状态明确可见
    运行清单 trajecta-core 任务恢复、验证、结果命令 生命周期、输入散列、行数、溯源记录
    任务记录与事件 trajecta-job CLI 状态、等待、事件与历史命令 持久化顺序、执行轮次 ID、终态含义
    CLI 机器响应 trajecta-cli Shell 脚本、AI 工具、CI 完整命令路径、诊断结构、标准输出内容

    testdata 中的公开结构定义描述磁盘格式和机器输出。Rust 类型是工作区内使用的编译期对应物。 Alpha 阶段仍可能随着公开格式调整 Rust 项，具体范围见 Rust API。

    常用贡献流程¶

    多数修改可以沿用以下工作顺序：

    1. 阅读目标 crate 的 src/lib.rs 顶部说明，以及离修改位置最近的模块文档。
    2. 编辑期间持续运行与改动最接近的单元测试或集成测试。
    3. 检查受到影响的公开格式，包括结构定义、示例、诊断、CLI 机器响应、运行清单和 SQLite 行。
    4. 运行测试与固定测试资料列出的格式化、静态检查、工作区测试和文档检查。
    5. 修改涉及读取器、数值路径、任务恢复或原生库时，再运行对应的真实资料或软件包门禁。
    6. 使用者可见行为发生变化时，同步更新两个语言目录。

    0.1.0-alpha.1 尚未提供动态插件加载。现有 crate 与 trait 边界可以支持后续设计，但当前不会 对外呈现扩展 API。状态说明见可扩展性。
