    教程¶

    本章用四个可以直接运行的小型项目介绍 Trajecta。每个项目都从案例配置开始，经过资料准备、 项目定稿和轨迹计算，最后读取结果。教程中的项目结构、数值引擎、任务队列和结果格式， 与正式研究使用的组件完全相同。

    四个项目各自突出一个主要变化：粒子群的生成方式、气象资料系列、计算区域或积分方向。建议 先完整运行一个项目，再修改时段、粒子数量或输出频率。这样更容易区分配置变化与资料问题。

    示例项目位于源码仓库和发行包的 examples/ 目录。配置片段直接从这些文件引入，页面所示内容 就是命令行程序读取的内容。

    四个教程¶

    教程 粒子群 气象资料 积分方向 资料准备
    区域填充水汽追踪 在全球区域内按等干空气质量生成粒子 CFSR 气压层 正向 四个时次的演示资料
    定时释放 从指定位置释放 1,000 个粒子 CFSR 气压层 正向 与快速入门共用演示资料
    气团输送 在有限区域内按等干空气质量生成粒子 ERA5 气压层 正向 资料下载助手和 CDS 请求
    平流层臭氧 在 PV60 臭氧掩膜内生成干空气载体粒子 ERA5 混合模式层 反向 资料下载助手和混合坐标准备流程

    四个示例均使用 1,000 个粒子，积分步长为 300 秒，只在物理时段两端输出粒子状态。运行配置 为工作进程预留 1 GiB 内存。十分钟的模拟区间便于快速检查资料和结果，也足以看清各种粒子群 和资料系列之间的差别。

    如何选择¶

    完成快速入门后，可以继续阅读区域填充教程。它详细解释如何把一个气象快照转换成等干空气 质量粒子，以及如何从结果中读取干空气载体质量和水汽状态。开展水汽来源、去向或停留时间 分析时，这一工作流通常最合适。

    如果研究从一个已知源区或排放时刻开始，可选择定时释放教程。案例会明确给出位置、释放时间、 垂直坐标和示踪物质量，并展示释放事件如何进入轨迹时间线。

    气团教程使用 ERA5 气压层资料和有限区域。它重点说明资料计划如何变成数据服务请求，以及粒子 穿过非周期边界后如何记为正常流出。

    臭氧教程使用 ERA5 的 137 个混合模式层。案例沿时间反向积分，并根据 PV60 规则初始化臭氧粒子。 教程还会说明对数地表气压、混合坐标系数和准备后 NetCDF 文件之间的关系。

    第一次运行 ERA5 示例

    先保留教程的短时段和 1,000 个粒子。确认资料准备、项目定稿和结果读取均可完成后，再扩大 区域或延长时段。

    各项目共用的流程¶

    四个项目采用同一套操作顺序：

    project validate
      ↓
project data-plan
      ↓
准备气象资料
      ↓
project finalize
      ↓
doctor --deep
      ↓
run --profile product
      ↓
result verify / inspect / trajectory

    project validate 检查当前已有的项目索引、案例和运行配置。此时气象文件可以尚未下载。 project data-plan 根据案例的时空范围和所需气象能力生成资料计划，其中包含资料系列、本地目录、 资料锁路径以及下载所需的时间锚点。

    资料准备完成后，项目定稿命令 project finalize 会检查本地文件，并为运行配置创建资料锁 （DatasetLock）。 资料锁固定文件清单、内容散列、有效时次、网格和垂直坐标等信息。doctor --deep 会进一步检查 本机配置、资料锁、气象文件和结果文件系统。

    run --profile product 把解析后的项目提交到本地任务队列。教程使用端点输出，因此时段起点和 终点各有一次粒子状态事件。计算结束后：

    • result verify 检查结果目录的完整性；
    • result inspect 汇总运行 ID、粒子、终止原因和产物；
    • result trajectory 按时间读取指定粒子的轨迹记录。

    示例项目的文件¶

    每个教程项目都由以下几部分组成：

    路径 用途
    trajecta-project.yaml 登记项目中的案例、运行配置和逻辑资料名称
    cases/*.yaml 描述模拟时段、区域、粒子群、数值方法、边界和输出
    profiles/*.yaml 指定本机资料目录、结果目录、读取器和工作进程资源
    locks/*.lock.json 记录项目定稿后实际采用的气象文件及其内容标识

    资料锁在项目定稿后生成。结果写入运行配置的 output_root，每次提交或重跑都会得到独立的 运行 ID 和执行轮次目录，已有结果不会被覆盖。

    需要修改教程时，直接编辑示例项目中的文件，然后重新运行 project validate 和 project data-plan。这样可以让案例文件始终作为唯一配置来源，避免笔记本、脚本和文档各自 保存一份逐渐分叉的配置。

    从教程扩展到正式研究¶

    扩大案例时，可以一次调整一个维度：

    调整项 主要影响
    延长模拟时段 增加气象时次、积分步数和运行时间
    增加粒子数量 增加气象查询、内存占用和状态记录
    缩短输出间隔 增加 SQLite 行数、结果目录体积和写入时间
    扩大有限区域 改变资料下载范围、边界位置和流出含义
    更换资料系列 改变变量准备、垂直坐标、时间频率和资料锁
    改变积分方向 改变起止时间关系、释放事件顺序和结果解读方式

    保留原始十分钟项目作为本机预检会很方便。换到新计算机、更新气象读取器或调整本机资源池后， 先运行这份小案例，再提交正式规模的任务。资料系列与轨迹方向列出了三类 气象资料的主要差异和覆盖规划方式。
